~/about

Why backend

I started with console programs in Java, a student record system and an inventory tracker for a jewellery shop, small worlds where every rule had to be written out by hand. That pulled me toward the part of an application nobody sees, where object-oriented design, clean data handling and exception handling decide whether the whole thing holds up.

My latest project, GasGuard, takes that further: a simulated IoT gas leakage monitor with a real-time dashboard, built around one rule, that a sudden spike must always raise a Warning before it becomes a Risk. I'm now deepening the foundation with Spring Boot, REST APIs and Hibernate, alongside DBMS and computer networks coursework, 260+ LeetCode problems, and two 24-hour hackathons.

GasGuard

IoT gas leakage monitoring system (simulated)

Built after reading about a Bengaluru gas-leak tragedy that claimed 8 lives, where nothing warned people early enough to react.

  • Three alert states: Safe, Warning and Risk
  • Rapid-rise prediction that catches sudden gas spikes and always raises a Warning before Risk, so users get time to react
  • Real-time dashboard on web and mobile with live state indicators, graph visuals and second-by-second event logs
